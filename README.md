# 3GPP Spec Q&A Chatbot

A Retrieval-Augmented Generation chatbot that answers questions over 3GPP
technical specification documents (21-series and 22-series). Answers are
grounded in the retrieved document excerpts, with the source file and
section always mentioned inline in the answer itself. If nothing relevant
is found, the API says so instead of guessing.

## Project layout

```
.
├── docker-compose.yml         # spins up Qdrant locally
├── final_data.json            # generated by partition_chunking.py, consumed by ingest.py
├── main.py                    # FastAPI app, exposes POST /ask
├── requirements.txt
├── .env.example
├── Data/                      # corpus: .docx files (3GPP specs)
└── backend/
    ├── pipeline.py            # retrieval() -> rerank() -> generate() -> answer
    ├── partition_chunking.py  # .docx -> chunks -> final_data.json
    └── ingest.py               # final_data.json -> Qdrant (hybrid dense+sparse embeddings)
```

## Requirements

- Python 3.10+
- Docker (to run Qdrant locally)
- A Google API key (Gemini, used for reranking-adjacent generation and grading)
- A Cohere API key (used for reranking retrieved chunks)

## 1. Install

```bash
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

## 2. Set environment variables

```bash
cp .env.example .env
```

`.env` (project root) needs:

| Variable | Description |
|---|---|
| `GOOGLE_API_KEY` | Google API key, used for Gemini (`gemini-3.1-flash-lite`) generation |
| `COHERE_API_KEY` | Cohere API key, used for `rerank-english-v3.0` |

Qdrant runs locally via Docker and does not require an API key.

Never commit `.env` — only `.env.example` (with dummy values) is tracked in git.

## 3. Start Qdrant

```bash
docker compose up -d
```

This starts Qdrant on `http://localhost:6333`. Confirm it's running:
```bash
curl http://localhost:6333/collections
```

## 4. Add the corpus

Place `.docx` 3GPP spec files into `Data/` at the project root.

## 5. Ingest (two steps)

**Step 1 — chunk the documents:**
```bash
python backend/partition_chunking.py
```
This reads every `.docx` file in `Data/`, partitions it into elements
(`unstructured`), chunks by section title (`chunk_by_title`), and writes
`final_data.json` at the project root. Each chunk includes its text, any
HTML table content, and metadata (`filename`, `chunk_id`, `parent_ids`).

**Step 2 — embed and upsert into Qdrant:**
```bash
python backend/ingest.py
```
This reads `final_data.json`, wraps each chunk as a LangChain `Document`,
and upserts into the Qdrant collection `MAVENIR_PROJECT` using hybrid
retrieval (dense embeddings via `BAAI/bge-base-en-v1.5` + sparse
embeddings via `Qdrant/minicoil-v1`).

**Re-running ingestion:** re-running `ingest.py` re-embeds and re-upserts
from `final_data.json`. If you re-run `partition_chunking.py` first
(e.g. after adding new files to `Data/`), regenerate `final_data.json`
before re-running `ingest.py` so Qdrant reflects the current corpus.

## 6. Start the API server

```bash
uvicorn main:app --reload --port 8000
```

Swagger UI (auto-generated by FastAPI): `http://localhost:8000/docs`

## 7. Call the API

**Health check:**
```bash
curl http://localhost:8000/health
```

**Ask a question:**
```bash
curl -X POST http://localhost:8000/ask \
  -H "Content-Type: application/json" \
  -d '{"question": "According to TS 22.001, what is the Information transfer rate attribute?"}'
```

Example response:
```json
{
  "answer": "According to TS 22.001 (section A.1), the Information transfer rate attribute describes the rate at which information is transferred..."
}
```

The answer always mentions the source file and section directly in the
text — there are no separate citation fields in the response, since the
generation step is instructed to include that information inline.

**An out-of-corpus question:**
```bash
curl -X POST http://localhost:8000/ask \
  -H "Content-Type: application/json" \
  -d '{"question": "What is the capital of France?"}'
```
```json
{
  "answer": "Sorry, I couldn't find anything relevant to that in the available documents."
}
```

## How it works

`POST /ask` runs a three-stage pipeline (`backend/pipeline.py`):

1. **`retrieval`** — hybrid similarity search (dense + sparse) against
   Qdrant, `k=15`, filtered to results scoring above `0.2`.
2. **`rerank`** — the retrieved chunks are reranked with Cohere's
   `rerank-english-v3.0`, keeping the top 8 most relevant.
3. **`generate`** — the top chunks are passed to Gemini with structured
   output, which writes a grounded answer and reports which chunk IDs
   it actually used. The prompt requires the filename (and section,
   where available) to always be mentioned in the answer text, and
   requires a "sorry, I couldn't find anything" response when no chunk
   answers the question.

If retrieval returns no chunks above the relevance threshold, the API
short-circuits and returns the "not found" message directly — this also
avoids a real crash risk, since Cohere's rerank endpoint returns a 400
error on an empty document list.
